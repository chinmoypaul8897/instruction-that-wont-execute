# `A1.md` — the advanced solution, and its two ablations

**Deliverable 1: the instructions that shape each agent.** Everything below is the text
actually sent to the model. `src/a1.py::assert_skill_matches_agents_md()` runs before the
first API call of every run and refuses to proceed if a line of the executed system
prompt is not present in this file, so a published instruction document cannot drift
away from the executed one.

The ordered procedure this arm follows is a separate shipped file,
[`A1-SKILL.md`](A1-SKILL.md), because it is `CONTEXT.md` §6's **capability 2** and one of
the arms below is defined by *not* receiving it.

## The system prompt — common preamble

Shared verbatim with `B0.md` and `B0-agent.md`:

```
You are an editor at the Office of the Federal Register (OFR).

Your job is to decide whether an amendatory instruction in a final rule can be
EXECUTED against the Code of Federal Regulations - that is, whether OFR will be able
to incorporate it into the CFR text.

An instruction fails to execute when, for example, the paragraph it targets does not
exist, the paragraph it adds already exists, quoted text it says to find is not
present in the section, set-out text is incomplete, or a citation or designation is
incorrect. When an instruction cannot be executed, OFR does not change the CFR and
NARA publishes a permanent editorial note recording that the amendment could not be
incorporated.
```

## The system prompt — A1's task block

**This is the change that matters, and it is the one `CONTEXT.md` §5 calls load-bearing.**
Every arm above receives it:

```
You will be shown the amendatory instructions for ONE CFR section from ONE final
rule, AND the text of that section as it stood immediately before the rule was
published.

You do NOT emit a verdict for the section. You emit ONE RULING PER AMENDATORY
INSTRUCTION, and the section verdict is derived from your rulings by the rule that a
section fails if ANY of its instructions fails. Naming which instruction fails, and
why, IS the task.
```

> **`verdict` is a DERIVED field of `resolution_trace`, not the primary output.**
> — `CONTEXT.md` §5

This is enforced in `src/a1.py::derive_output()`, not merely requested. The model has no
channel through which to emit a section verdict; the harness computes it from the
per-instruction rulings. **The consequence is that A1 cannot be right for the wrong
reason** — it cannot score a correct `WILL_FAIL` by sensing that a section looks bad. It
has to name the instruction and the class.

## The system prompt — the tool block

Appended for `A1-iter1` and `A1` only:

```
You have a deterministic tool, `cfr_resolve`. It reads the frozen point-in-time section
text and answers two independent questions about one instruction: is this paragraph
designation declared in the section, and is this quoted anchor present in it. It cannot
be wrong about the text; it can only be asked the wrong question.

You may call it several times in a single turn - one call per instruction you are
checking - and doing so is preferred.
```

`A1-minus-tool` receives instead:

```
You have NO tool. Check each instruction against the section text yourself, by reading it.
```

## The system prompt — the output contract

Appended for every arm:

```
Return ONE JSON object and nothing else. No prose before or after it, no markdown fence:

{"instructions": [
  {"instruction_index": 1, "operation": "amend", "anchor": null, "designation": null,
   "executes": true, "failure_class": null, "why": "umbrella; asserts no target"},
  {"instruction_index": 2, "operation": "remove", "anchor": "1916 Race Street",
   "designation": null, "executes": false, "failure_class": "quoted-text-not-present",
   "why": "cfr_resolve: found=false, level=none at all three declared levels"}
]}

One record per instruction, in document order, NONE OMITTED - umbrellas included.
`executes: false` REQUIRES a `failure_class`, which must be exactly one of:
  target-does-not-exist · target-already-exists · quoted-text-not-present ·
  incomplete-set-out-text · incorrect-citation-or-designation
`executes: true` takes `failure_class: null`.
Do NOT emit a section-level verdict. It is derived from these records.
```

## The tool, as the model sees it

Name `cfr_resolve`. Implementation `src/cfr_resolve.py`, CH-05, unmodified by this
chunk — pure, no network, no clock, no randomness.

**The title, part, section and as-of date are bound by the harness and are not
parameters the model can set.** It may vary only `designation`, `quoted_text` and
`instruction_index`. The model therefore cannot redirect the resolver at a different
section, a different date, or any text outside the frozen point-in-time corpus. That is
a containment property, not a convenience: an arm that could choose its own evidence
would not be measuring the same task as the baselines.

| Field returned | Meaning |
|---|---|
| `designation_exists` | the paragraph is declared in the section. **`null` = not asked**, which is not `false`. |
| `siblings` | what *does* exist at the deepest level on the path to the target |
| `found` | the quoted anchor is present |
| `level` | `exact` · `whitespace-collapsed` · `alphanumeric-only` · `none` — the normalisation the match needed, **reported, never applied invisibly** |
| `char_offset` | where the anchor starts **in the caller's own string** |

`found` and `designation_exists` are **independent**. Neither is derived from the other.

**When the tool refuses, the refusal is the answer.** `cfr_resolve` raises rather than
guessing when handed something that is not a parenthesised designation path; that error
is returned to the model as the tool result. Inventing a target is the defect this agent
exists to catch, so the tool does not commit it either.

## The emitted artifact — `CONTEXT.md` §5's output contract

One JSON object per item, at `docs/evidence/ch06-a1/<arm>-rep<N>-artifacts.jsonl`:

```json
{ "verdict": "WILL_FAIL", "failing_designation": "(a)(38)",
  "failure_class": "target-already-exists",
  "resolution_trace": [ { "instruction_index": 3, "operation": "add", "anchor": null,
    "designation": "(a)(38)", "found": false, "level": "none",
    "designation_exists": true, "siblings": ["(a)(1)", "..."], "char_offset": null,
    "model_ruling": { "executes": false, "failure_class": "target-already-exists",
                      "why": "..." } } ],
  "needs_human_review": true, "review_reason": "C3 designation (a)(38) is touched by ...",
  "tool_calls_made": 4, "instructions_unruled": [] }
```

Each trace record carries **three separable things**, and that separation is the point:

1. **what is true** — `found`, `level`, `designation_exists`, `siblings`, `char_offset`,
   computed by the harness from `cfr_resolve` for **every arm, including
   `A1-minus-tool`**, because these are facts about the *item*, not about the arm;
2. **what the model said** — `model_ruling`;
3. **whether it looked** — `tool_calls_made`.

Holding all three in one file is what makes `plan.md` CH-06's **tool-availability-versus-
tool-use gap** measurable at all, rather than an average from which use must be inferred.

### An incomplete emission is a FAILURE, never a skip

Fixed in `src/a1.py`'s docstring **before the runs**, following `GOOD.md` §1:

- a **targeted** instruction (carrying an anchor or a designation) with no model record
  is **not ruled**; any item with a not-ruled instruction derives `verdict: null`, which
  `src/score.py` charges as wrong, and routes to the human queue. **An agent cannot buy
  `WILL_EXECUTE` by omitting the record that would have failed.**
- an **umbrella** instruction — no anchor, no designation, e.g. *"Section 75.6 is amended
  as follows:"* — is auto-filled `executes: true` if its record is absent. It asserts
  nothing that can be false, and the leniency is unexploitable because there is no target
  to be wrong about.
- a `failure_class` outside `CONTEXT.md` §5's **closed** five-value NARA vocabulary is
  **dropped, not adopted**, and the item is routed. The vocabulary does not grow because
  a model invented a sixth name for something.

## The human checkpoint — three deterministic conditions

Computed by `src/a1.py::human_checkpoint_reasons()` **from the trace, in code**. The
model is not asked when to escalate: an agent that decided that for itself would escalate
whenever it felt unsure, which is a confidence report, not a checkpoint.

| | Condition | Why it is not the agent's to decide |
|---|---|---|
| **C1** | `level: "none"` **and** `designation_exists: true` | the paragraph is there and the quoted text is not — the two halves of the instruction disagree |
| **C2** | both paths asked and `found != designation_exists` | the designation path and the anchor path returned opposite answers |
| **C3** | a designation is touched by **two or more** instructions | instruction *k* changes what *k+1* will find, and the ordered-state ledger that would resolve it is **not built** (ruling R-01, counted removal #3). The agent does not model execution order and must not pretend to. |

A routed item emits both readings and the full paragraph trace, and `RunLogger` writes a
`human_checkpoint` record into its trajectory. `CONTEXT.md` §9: *"Unresolved cases route
to a named human checkpoint with both readings and the paragraph trace."*

**Routing does not excuse the item from the metric.** A routed item is still scored on
its derived verdict, because an agent that could opt out of the denominator by escalating
would have found a way to be measured only on the questions it liked.
