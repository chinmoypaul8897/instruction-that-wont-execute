# CH-14a — the trajectory selection rule

**Status: PUBLISHED, APPLIED, and — on this tree — NOT INVOKED, because nothing needed
to be dropped. See `inventory.md` and `QUESTIONS.md` Q27.**

## Why a rule exists at all

`QUESTIONS.md` Q2, consequence **C2**, is binding spec:

> *The PDF requires "**representative** trajectories for every agent you used", not all
> of them. Ship a curated representative set in the zip; ship the complete set in the
> git repo and link it from the Description. **Record the selection rule so the
> curation is auditable.**"*

A curation nobody can audit is indistinguishable from dropping the runs that looked bad.
So the rule is fixed in writing **before** it is applied, and applying it is a script
whose output is committed beside it.

## Provenance of the rule text — the ordering that makes this auditable

The five clauses below are **quoted from the CH-14a chunk prompt**, committed verbatim
at [`prompts/CH-14a.md`](../../../prompts/CH-14a.md) §1b. The prompt was issued by the
architect before this session read a single byte of trajectory. **The rule therefore
pre-dates every measurement in `selection-applied.md`**, which is the property that
makes the curation auditable rather than retrofitted. Nothing in the rule was written,
reworded or reordered after a size was seen.

## The rule

| id | clause |
|---|---|
| **R1** | one trajectory per **agent class** — `build`, `arms`, `probe` |
| **R2a** | for the arms: the **first** run |
| **R2b** | for the arms: the **median-cost** run |
| **R2c** | for the arms: one containing a **`retry`** record |
| **R2d** | for the arms: one containing a **`human_checkpoint`** record |
| **R3** | **every run whose verdict disagreed with gold** — failures are never filtered out |
| **R4** | everything else stays in git history and is linked from the submission Description |

### Tie-breaks, fixed here so no choice is made with a size in view

- "First" and "one containing" resolve by **sorted repo-relative path**, ascending.
  No timestamps, no cost, no accuracy.
- **Median-cost** is the element at index `(k-1)//2` of the arms runs sorted by
  `(imputed_usd, path)` — the lower median when `k` is even. Cost is summed from
  `docs/evidence/runs/cost_ledger.csv` over the `run_id`s the trajectory contains.
- The **unit of shipping is the file**, not the item-level run. A file is selected if
  **any** clause selects **any** run inside it. Selecting a fraction of a bundle would
  contradict `src/arms.py::bundle()`, which promises *"EVERY RECORD SURVIVES — nothing
  is sampled, summarised or dropped."*

## What the rule selects on this tree

Computed by [`apply_selection.py`](apply_selection.py), output committed at
[`selection-applied.md`](selection-applied.md):

- **17 of 33** trajectory files, **23.35 MB of 37.73 MB (61.9%)**.
- **R3 alone selects all 15 of 15 arms trajectories.** No arm scores 1.000 on this
  corpus — the best, A1, scores 0.7195 — so every arm run contains items whose verdict
  disagreed with gold, and a clause that never filters out a failure necessarily keeps
  every arm file. That is the clause working, not a loophole in it.
- The 16 unselected files are 7 `build` session exports and 9 `probe` runs. Between
  them they are 14.38 MB raw and **3.42 MB compressed** — 33.6% of a 10.18 MB upload
  that has 39.82 MB of headroom. Dropping all sixteen would take the upload from
  10.18 MB to 6.76 MB.

  *(This figure was first written by hand as "2.60 MB / 25.6%" and was **wrong**. It is
  now generated by `apply_selection.py` from the archive itself and printed in
  `selection-applied.md`. Hard rule 14: a number without its generating script is not
  evidence, and this one proved the point on itself.)*

## Applied to the archive: NOT INVOKED

**Nothing is dropped from the archive.** The rule is a contingency and the contingency
did not arise:

`git archive --format=zip HEAD` is **10,182,500 B = 10.18 MB** against a **50 MB** cap.
The complete trajectory set is a **superset** of the selection, so shipping all of it
satisfies C2's "representative" requirement *a fortiori* — you cannot fail to be
representative by including the representatives **and** everything else.

Invoking the rule here would cost the submission real evidence — seven build-session
transcripts that are deliverable 4's only trace of how the coding agents were directed
— to recover 3.42 MB of an already 4.9×-under-cap upload. **That trade is refused.**

## When this rule WOULD be invoked

If a future commit pushes `git archive --format=zip HEAD` above **45 MB** — the
threshold `.githooks/pre-commit` now enforces — the rule is applied in clause order
R1 → R2a → R2b → R2c → R2d → R3, and `apply_selection.py` is re-run so the resulting
curation ships with its own audit. Under **R4** the complete set remains in git history
and the submission Description links it.

**No clause of this rule may be weakened to make an archive fit** (hard rule 5). If the
selected set alone exceeded the cap, that is a red result and it ships as red — with
the excluded material reachable in git.
