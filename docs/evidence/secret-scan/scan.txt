LIMITATIONS, stated rather than left for a reviewer to find:
  1. Regex prefix matching only. A secret with no recognisable provider
     prefix - a bare 40-char hex string - is caught only if it is assigned
     to a variable named key/secret/token/password.
  2. Binary blobs are skipped, not decoded. Count reported above.
  3. NO entropy analysis. gitleaks proper does this and would flag
     high-entropy strings this sweep passes over. This is the single
     largest gap between this script and the tool it stands in for.
  4. Only refs reachable from `--all`. A secret in a dangling object no ref
     reaches is not scanned.
  5. Advisory classification takes the FIRST prefix match per blob. A file
     whose first `sk-ant-` is a regex definition and whose second is a real
     key would be misclassified. No such file exists here - every blocking
     count is zero - but the limitation is real and is stated.
  6. Point-in-time result for the commit named at the top.
